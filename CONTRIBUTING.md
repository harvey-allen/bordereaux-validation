# Contributing

- Run `scripts/ci.sh` and ensure it passes before committing.
- Maintain a minimum combined (frontend + backend) coverage of 75%.
- New features and behavioural changes must include relevant documentation updates.
- Follow existing code style, naming, and project conventions.
- Keep pull requests focused, self-contained, and easy to review.
- Prefer small, incremental changes over broad refactors in one PR.
- Add or update tests alongside functional changes.
- Keep API and schema changes synchronized across backend and frontend usage.
- PR descriptions must include:
	- Current coverage percentage
	- Coverage change vs target branch
	- Summary of new tests added
	- Any intentionally excluded areas and justification
